01 / SCOPE

From observations
to application decisions.

Which information does a receiving application actually require, and how can its sufficiency be demonstrated?

Traditional communication systems transport source data without asking whether the downstream task needs those observations in full. LESS studies the preceding engineering question: how should task-relevant information be specified, extracted, represented, placed across device, edge and cloud, and delivered to the application?

The workshop connects semantic, goal-oriented and task-oriented communication with application-aware sensing, Edge AI, distributed inference and experimentally validated networked systems. The emphasis is on the complete observation-to-decision chain, not semantic abstraction in isolation.

02 / APPLICATION-GROUNDED EVALUATION REQUIREMENT
CORE SUBMISSION REQUIREMENT

A concrete application is
required, not illustrative.

Every submission must be grounded in a concrete and credible application scenario. An application presented only as motivation is not sufficient. Authors are expected to establish what the downstream application actually needs and to measure the consequences of communicating a derived representation rather than the original observations.

Each paper is expected to make the following explicit
  1. 01

    Source observations

    Which physical measurements, signals, traces or original source data are available?

  2. 02

    Application & requirements

    What downstream task is being performed? Which information does that task require?

  3. 03

    Extracted representation

    How is task-relevant information extracted and represented (e.g., event, state, intent, feature or embedding)?

  4. 04

    Communicated vs. omitted

    What is sent to the receiver, and which source-level information is not communicated?

  5. 05

    Application-level performance

    How well does the receiving application accomplish its task using the communicated information?

  6. 06

    System-level impact

    What changes in communication, computation or overall system operation, and what trade-offs are observed?

NOT SUFFICIENT ON ITS OWN

A generic semantic encoder evaluated only through compression, reconstruction or an abstract similarity score, with an application merely cited as a possible motivation.

APPLICATION-GROUNDED CONTRIBUTION

A wearable sensing system specifying which movement variable a downstream task needs, extracting it from IMU data, and evaluating task performance together with transmitted information and processing costs.

Physical deployments are encouraged but not mandatory. Real datasets, traces, prototypes, testbeds, emulation environments and realistic system models are all welcome when the application-level evaluation is credible.

03 / CALL FOR PAPERS

Call for
Papers.

LESS 2027 · Learning to Extract and Send Semantics

Application-grounded extraction, representation and communication of task-sufficient information.

Networked intelligent systems operate on heterogeneous streams from sensors, wearables, biomedical platforms, microphones, cameras, radar and industrial equipment. Yet many receiving applications require only a task-sufficient representation rather than the complete source stream. LESS invites research on identifying this information, deriving it from observations, communicating it across networked systems, and experimentally verifying its sufficiency.

The workshop welcomes methodological advances together with implementations and experimental validation. Contributions should connect the original observations, the application information requirements, the representation and communication mechanism, and the resulting application- and system-level effects.

TECHNICAL PERSPECTIVE

Research questions

  • How are downstream information requirements expressed, negotiated or updated?
  • Which representations preserve information sufficient for the application task?
  • Where should extraction occur across device, edge, network and cloud resources?
  • How are semantic freshness, uncertainty, relevance and requests for further information handled?
  • How can application utility and communication/computing costs be measured jointly?
TOPICS OF INTEREST

Technical areas.

Including, but not limited to, the following topics. The application-grounded requirement applies across all areas.

01

Requirements & representations

  • Application-grounded semantic communication
  • Application-level semantic extraction
  • Task-sufficient semantic representations
  • Goal-oriented and task-oriented communication
  • Representation of application information requirements
  • Semantic interfaces between applications and networks
02

Extraction & distributed intelligence

  • Semantic extraction from continuous sensor streams
  • Multimodal semantic representations
  • Edge AI for semantic extraction
  • Device–edge–cloud semantic processing
  • Distributed and split inference
  • Adaptive semantic representations and semantic update generation
03

Communication & adaptation

  • Event-, state-, intent-, token-, feature- and embedding-based communication
  • Semantic filtering and relevance-aware communication
  • Application-aware and semantic-aware networking
  • Semantic freshness and Value of Information
  • Uncertainty and confidence in semantic representations
  • Processing and prioritization of semantic traffic
  • Mechanisms for requesting additional or source-level information
04

Sufficiency & experimental evidence

  • Semantic sufficiency metrics and interoperability
  • Benchmarks for application utility versus communicated information
  • Experimental systems, datasets, testbeds and real-world deployments
APPLICATION DOMAINS

Where this applies.

Relevant applications include digital health, wearable systems, sports sensing, speech and audio, industrial IoT, robotics, smart environments, intelligent transportation, autonomous systems, and integrated sensing and communication.

Cross-domain submissions are especially encouraged when they connect a concrete application need to a measurable communication or computing benefit.
